# Runbook: High CPU Utilization & Load Average Alert (RB-OPS-104)

## Описание инцидента
Алерт срабатывает при средней утилизации процессора свыше 85% на протяжении 5 минут, либо при значении Load Average (1m), превышающем количество логических ядер процессора в 2 и более раза.

## Первичная диагностика
1. Оценить общую утилизацию процессора и среднюю загрузку (Load Average):
   `uptime` или `vmstat 1 5`
2. Определить 10 процессов, потребляющих наибольшее количество процессорного времени (%CPU):
   `ps aux --sort=-%cpu | head -n 11`
3. Оценить распределение времени между user (пользовательский код), system (системные вызовы ядра) и iowait (ожидание диска):
   `top -b -n 1 | head -n 15`
4. Проверить потоки конкретного проблемного процесса:
   `top -H -p <PID>` или `pidstat -u 1 3 -p <PID>`

## Типовые причины высокого CPU
1. **Высокий %user:**
   - Зацикливание потока приложения (бесконечный цикл, неоптимальный алгоритм).
   - Атака типа DoS/DDoS или резкий всплеск пользовательского трафика.
   - Компрометация сервера (скрытый криптомайнер).
2. **Высокий %system:**
   - Чрезмерное количество контекстных переключений (context switches) или прерываний (interrupts).
   - Перегрузка сетевого стека большим количеством мелких пакетов.
3. **Высокий %iowait:**
   - Процессор простаивает в ожидании ответа от СХД или медленного диска (см. `runbook_disk_alert.md`).

## Регламент устранения
1. Зафиксировать PID, команду и пользователя процесса-виновника для отчёта в инцидент-тикет.
2. Если процесс является сторонним или зависшим рабочим воркером:
   - Отправить сигнал `kill -15 <PID>` (мягкое завершение).
   - При отсутствии реакции через 30 секунд: `kill -9 <PID>`.
3. Если процесс — это системный сервис (например, PostgreSQL, Nginx, Java backend):
   - Запрещено выполнять безусловный kill.
   - Проверить текущие тяжелые запросы (`pg_stat_activity` / slow logs) или выполнить graceful reload сервиса.
