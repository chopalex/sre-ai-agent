# Runbook: Network Latency & Packet Loss Diagnostic (RB-OPS-102)

## Описание инцидента
Алерт срабатывает при потере пакетов свыше 2% на сетевом интерфейсе или задержке RTT более 80 мс до шлюза/DNS.

## Диагностические команды
1. Проверить состояние сетевых интерфейсов, ошибки и дропы:
   `ip -s link`
2. Проверить таблицу маршрутизации и шлюз по умолчанию:
   `ip route show`
3. Проверить открытые сокеты, слушающие порты и установленные соединения:
   `ss -tulwn`
4. Проверить очередь соединений в состоянии TIME_WAIT / CLOSE_WAIT:
   `ss -s`
5. Проверить резолв имен через корпоративный DNS:
   `nslookup -timeout=2 internal.service.local 127.0.0.1`

## Анализ узких мест
- Если наблюдаются `rx_dropped` / `tx_dropped`: проверить заполнение кольцевых буферов сетевой карты.
- Если зависают TCP-соединения: проверить параметры `net.ipv4.tcp_max_syn_backlog` и `net.core.somaxconn`.

## Безопасность
Запрещено изменять правила iptables/nftables без согласованного Change Request (CR).
Разрешен только просмотр: `iptables -L -n -v` или `nft list ruleset`.
